{{- if not .Values.controller.persistence.enabled }}

WARNING: controller.persistence is disabled, so the signed TUF repository lives in an emptyDir.
The controller numbers each generation from that state. Once this repository has published, losing
the pod means the controller fails closed — it will refuse to re-initialize at version 1 over a
store already serving a later generation, and publishing stops until the state is restored.
This setting is only safe for a repository that never needs to survive a restart.
{{- end }}

{{- if not .Values.certManager.enabled }}

This release does NOT create its TLS material. The gateway stays in ImagePullBackOff-adjacent
limbo (ContainerCreating, unmounted Secret) until both of these exist:
  - {{ .Values.gateway.tlsSecretName }}   the gateway's server certificate (tls.crt/tls.key) and the CA agents are verified against (ca.crt)
  - {{ .Values.gateway.issuingCaSecretName }}       the fleet CA *including its private key*, so /enroll can sign node CSRs
Set `certManager.enabled=true` to have the chart issue both from a self-signed fleet root.
{{- end }}

{{- if eq .Values.gateway.service.type "ClusterIP" }}

The gateway Service is ClusterIP, so nodes outside this cluster cannot reach it. Set
`gateway.service.type=LoadBalancer`, or enable `gateway.ingress` on a TLS-PASSTHROUGH controller.
The gateway terminates mutual TLS itself; a proxy that terminates TLS strips the client certificate
that IS the node's identity.
{{- end }}
